[feature] Read emphasis beside CJK punctuation as CJK writers mean it, with a `punctuation` mode for Markdown import and export

CommonMark doesn't let `**` open or close between a letter and punctuation, so `**你好。**世界` reads with literal asterisks. Import in both packages now follows the [CommonMark CJK-friendly amendment](https://github.com/tats-u/markdown-cjk-friendly) by default, as `markdown-it-cjk-friendly` and `micromark-extension-cjk-friendly` do: Markdown reads as CommonMark reads it except beside Chinese, Japanese and Korean characters and punctuation, where `*`, `_` and `~~` markers open and close as their writer meant, and a variation selector before a marker reads as the character it follows. Export still writes, by default, Markdown that strict CommonMark and GFM readers read the same way, with a character reference where a marker needs one (`**你好。**&#19990;界`).

`@lexical/markdown`'s `$convertFromMarkdownString`, `$generateNodesFromMarkdownString`, `$convertToMarkdownString` and `$convertSelectionToMarkdownString` take an options object in place of the `shouldPreserveNewLines` argument (`MarkdownImportOptions` and `MarkdownExportOptions`, which also hold `shouldPreserveNewLines` and, for import, `shouldMergeAdjacentLines`). Its `punctuation` option is `'cjk-friendly'` (the import default) or `'strict-commonmark'` (the export default). `@lexical/mdast`'s `MdastExtension` takes the same modes as `importPunctuation` and `exportPunctuation`. With `'cjk-friendly'`, export writes such CJK text as typed (`**你好。**世界`), for readers that follow the amendment. `@lexical/mdast` now writes references beside `~~` as it does beside `**`, so that strikethrough beside punctuation reads back with a strict import too, and reads an emoji or another character outside the Basic Multilingual Plane as the punctuation CommonMark counts it as, so a letter beside a run that starts or ends with one goes out as a reference; with strict export the emoji does too where micromark, which reads it as a letter, would otherwise read the run differently (`Hell&#x6F;**&#x1F389; launch**`, or `Hell&#x6F;**🎉 launch**` with CJK-friendly export). Both packages read a variation selector before a marker as the CJK-friendly readers do, writing it or the character beside the run as a reference where readers differ (`**©︎**&#50;024`), and before a closing `~~`, which `micromark-extension-cjk-friendly-gfm-strikethrough` would otherwise leave open (`~~Done ✔&#xFE0E;~~`). `@lexical/mdast` also writes U+FEFF, U+2028 and U+2029 as a reference beside a marker where micromark, which reads them as whitespace, and other readers would read the run differently. `@lexical/markdown` again reads a vertical tab (U+000B, which Office writes for a soft line break) beside a marker as whitespace, as commonmark.js, markdown-it and micromark do, so formatting beside one round-trips as it did before Unicode punctuation flanking (#9747). `@lexical/mdast`'s typed shortcuts read markers as `importPunctuation` does, so typing `中文**「强调」**` applies bold. `@lexical/mdast` now needs `micromark-core-commonmark` 2.0.4 and `mdast-util-to-markdown` 2.2.1; with them its strict import no longer lets a `*` run open beside a `_` run (`foo**_bar_**baz`), as CommonMark reads it and as the CJK-friendly import does.

Verify: Markdown such as `**你好。**世界` or `中文**「强调」**` imports as bold in both packages, as it did in `@lexical/markdown` before it followed CommonMark's Unicode punctuation; pass `punctuation: 'strict-commonmark'` (or `importPunctuation`) to read it as CommonMark does. `@lexical/mdast` export of strikethrough that starts or ends with punctuation beside a letter, and of formatting that starts or ends with an emoji beside a letter, now holds character references (`~~你好。~~&#x4E16;界`, `Hell&#x6F;**&#x1F389; launch**`), so check export snapshots; so does strikethrough that ends with a variation selector (`~~Done ✔&#xFE0E;~~`). `@lexical/mdast` also escapes the backslashes right before a character that goes out as a reference beside a marker (`a\\&#x62;**。**`), so the reference doesn't come out escaped. Markdown exported before with an emoji (`@lexical/mdast` only) or a text variation selector at the inner edge of a run beside a letter, such as `Hello**🎉 launch**` or `**©︎**2024`, now imports with literal markers, as the CJK-friendly readers read it, while strict CommonMark readers, which don't count a selector as punctuation, still read `**©︎**2024` as bold; import with `'strict-commonmark'` to keep the earlier reading of stored Markdown. In `@lexical/mdast`, `'strict-commonmark'` import now reads the `**` of `foo**_bar_**baz` as literal, around italic `bar`.
