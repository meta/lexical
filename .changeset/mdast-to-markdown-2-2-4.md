[fix] Update `mdast-util-to-markdown` to 2.2.4, which writes touching emphasis and strong without joining their markers, keeps a link whose URL starts with `<`, leaves out bold, italic or strikethrough that a selection only touches, and no longer takes quadratic time on many touching runs of attention

Verify: Bold `a ` followed by bold italic `b` should export as `**a _b_**` (before, `**a *b***`), and bold `ab` followed by italic `cd` as `**ab**_cd_` (before, `**ab***cd*`). Where `_` would sit inside a word, the letter beside it is written as a character reference: bold `ab` followed by bold italic `cd` exports as `**a&#x62;_&#x63;d_**` (before, `**ab*cd***`). All of them read back as the same texts and formats. With `exportPunctuation: 'cjk-friendly'`, the references beside such an `_` stay: `a`, bold italic `。`, italic `世` and `b` export as `&#x61;*__。__&#x4E16;*&#x62;` (before, `a***。**世*b`). A link to `<a` should export as `[t](<\<a>)` and read back as a link to `<a` (before, `[t](<a)`, which reads back as text; a link to `<a>` read back as a link to `a`). With bold `ab` followed by `cd`, `$convertSelectionToMarkdownString()` of a selection from the end of `ab` into `cd` should export as `c` (before, `****c`), and with strikethrough `ab` followed by `cd`, the same selection should export as `c` (before, `~~~~c`, which reads back as a code block).
