[feature] `DraggableBlockPlugin_EXPERIMENTAL` drags list items on their own: the handle targets the block under the pointer at any depth (a list item in a nested list, not the whole list), an item can be dropped into any list or outside a list (where it gets a new list of the same type), and a block that is not a list item dragged over a list lands next to that list, so the drop line only shows where the drop will happen. The drop line is indented to the target's left edge. The blocks of a multi-block named slot get a handle too; a single-line slot value does not. By default a shadow root (a table, a layout container) is still dragged as one block. The new optional `$getBlockBehavior` prop decides per node whether a block is `'draggable'`, `'atomic'` (one unit, nothing inside gets a handle), `'transparent'` (no handle, but the blocks inside can get one) or `'ignored'` (no handle for it or anything inside); blocks can be dropped into a shadow root whose blocks have handles. A list whose last item is dragged out is removed, and a shadow root whose last block is dragged out keeps an empty paragraph.

Verify: in the playground, hover a list item (the handle appears for the item), drag it below another item of the same, a nested or another list, drag it below a paragraph, and drag a paragraph onto a list item. Insert a collapsible: the handle over its title drags the whole collapsible, the paragraphs of its content have their own handles, and a paragraph can be dragged into and out of the content. Insert a pull quote: the paragraphs of the quote have their own handles, the attribution does not.
