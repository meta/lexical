[breaking] `@lexical/y/offline`: `replayUnsyncedEdits` and `recoverYOfflineEdits` take a required `leftovers`, and with `leftovers: {wrap}` write every block that cannot be replayed into the document, in the update that replays the rest (new block ids, one undo step); `wrapLeftoversAsQuote(label)` is a ready wrapper; and a required `autoReplay` (`'replayable'`, `'none'` or `{maxBaseAge}`) says whether an old copy is replayed by itself

A block of a report that a replay could not apply (both sides changed it, it was deleted since, the report has no base or no block ids) used to exist only in the call's result, for a panel the app had to build; an app without one lost the edit. Now `leftovers` says where such blocks go, and has no default: `{wrap, placement?}` writes them after the block they conflict with (or at the top), through the app's wrapper, and marks the stored capture `resolved`; `{handle}` gives them to the app, which then deletes the capture itself. `autoReplay` has no default either: `'replayable'` is the behavior before, `'none'` sends every block the user added or changed to `leftovers`, and `{maxBaseAge}` does so for a copy older than that (the capture's new `baseAt`, when its base was last confirmed on the server). The result gains `inserted`, `leftovers` and `handled`; `YReplaySkipReason` gains `'in-document'` and `'not-auto-replayed'`; `YUnsyncedReport` gains `order` and, without block ids, `shifted` (the blocks the current document holds by content); `YOfflineCapture` gains `resolved`, `claimedAt`, `claimedWrite` and `baseAt`; `YOfflineLoaded` gains a required `baseAt: number | null` (code that builds one by hand must set it: `null` when unknown); `YOfflineReport` gains `baseAt`; a store's `claimCapture` takes an optional `retake` and a slot's `confirm` an optional `confirmedAt`. With `wrap`, a capture whose blocks were only moved is resolved and deleted once the server holds the document. These APIs are `@experimental`.

Migration: with `wrap`, `replayUnsyncedEdits` throws (nothing written) when the editor update fails or the binding does not store it, instead of returning blocks as `'not-written'`; a direct caller catches it (`recoverYOfflineEdits` returns it as that capture's error and keeps the capture). Add `autoReplay: 'replayable'` (the behavior before) or `autoReplay: {maxBaseAge: 3 * 24 * 3600 * 1000}` and `leftovers: {wrap: wrapLeftoversAsQuote('Offline edits that did not merge')}` (from `@lexical/y/offline`) to each call, to have the blocks written into the document. To keep resolving them in a panel of your own, pass `leftovers: {handle: (blocks, {captureId}) => showInPanel(captureId, blocks)}` instead; nothing else changes for such an app, except that a block the document already holds as the user had it is reported as `'in-document'` instead of `'changed-since'` or `'not-replayable'`. A JavaScript caller that passes no `leftovers` or no `autoReplay` gets a `TypeError` that names the choices. A panel's button that reapplies one block (`only`) passes `autoReplay: 'replayable'`.

Detect: code that reads `'not-written'` from a `replayUnsyncedEdits` call with `wrap` (it throws now); calls to `replayUnsyncedEdits(` and `recoverYOfflineEdits(` (every call: the TypeScript and Flow errors are "Property 'leftovers' is missing ... required in type 'YLeftoversRequiredPassWrapOrHandle'" and "Property 'autoReplay' is missing ... required in type 'YAutoReplayRequiredPassReplayableNoneOrMaxBaseAge'"); code that constructs a `YOfflineLoaded` by hand (the error is "Property 'baseAt' is missing"; pass `baseAt: null` or the stored value); code that compares a whole `YReplayResult` with `{applied, notApplied}`, or switches exhaustively over `YReplaySkipReason`; a hand-written `YOfflineStore` whose `claimCapture` should now also set `claimedAt` and honor `retake`, and whose slots' `confirm` should store `confirmedAt` (returned by `load` as `baseAt`).

Codemod: none; whether the blocks are written into the document or handled by the app is a product decision.

Verify: at stage `'replay'`, a document recovered after an edit both sides made holds the user's version of the block after the current one, under the wrapper's label, and one undo removes it together with the reapplied blocks; the capture is gone from the store once the document has synced.
