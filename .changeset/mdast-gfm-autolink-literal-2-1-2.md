[fix] Update `mdast-util-gfm-autolink-literal` to 2.1.2, and with `MdastGfmExtension` or `MdastAutolinkLiteralExtension`, link a `www.` or `http(s)://` URL only where micromark finds one in the Markdown as written, as GitHub does in comments, so a URL typed as text reads back as text

Verify: Text `https://x.com` exports as `https\://x.com` and `www.x.com` as `www\.x.com`, as before, and both now read back as text (before, as links). On import, a URL that an escape or a character reference writes (`&#x77;ww.x.com`, `www&#46;`) now stays text, and so does a `www.` URL right after `.`, `!`, `"` or a code span (`see .www.x.com`, `wow!www.x.com`, `"www.x.com"`), as in GitHub comments (before, the URL linked). A URL that GitHub links but micromark does not find in the source now imports as text too, such as one with a `.` after it (`www._x.com. next`, where GitHub links `www._x.com`) or a `_` after a non-ASCII letter in its domain (`www.café_bar.com`). URLs that micromark finds in the Markdown as written still link, with the characters as written, such as `https://x\.com`. Emails still link where GitHub finds them in the decoded text, so one whose `@` is escaped or written as a reference (`a\@b.co`, `a&#64;b.co`) links, as on GitHub, but a reference before an unescaped `@` still cuts an email short, as before (`a&#98;c@d.co` links `c@d.co`, where GitHub links `abc@d.co`); `mailto:a\@b.co` now links whole (before, only `a@b.co`), and plain `mailto:a@b.co` still links only `a@b.co` (GitHub links it whole). An email inside a URL that stays text links, as on GitHub: `https\://x.com/a@b.co` links `a@b.co`, and `www\.x\@b.co`, the export of text `www.x@b.co`, links as an email. A URL in text that another mdast transform adds before the GFM transform runs no longer links. With `exportPunctuation: 'strict-commonmark'`, Markdown `FTP://a.co/　©_a_` (U+3000 before `©`) imports and exports as `FTP\://a.co/　&#xA9;_a_` (before, unchanged, which cmark-gfm read as one link). The export rule that escaped the `.` of `www.` before any character now comes from the library, with the same output for `www.`. A `.` after a single `w` is no longer escaped: text `new.file` exported as `new\.file` and now exports as `new.file`, which reads back the same. After a code span, a bare literal that follows the first one in the paragraph now exports as `[text](url)` too, because the first one no longer reads back as a link; both read back the same.
