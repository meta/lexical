[fix] Loading a document no longer opens (or closes) a format on its own while the format's other end stays blocked. The load repair could integrate a lone format item, such as a bold opener whose closer still waits for a missing update, and bold then ran on over text the encoding document, a plain load and the healed document all show plain. The repair now plans its suffixes exactly before applying any and holds back a run that carries only format items while a format item with the same key stays pending, unless content (text, an embed, a node) depends on it; it still recovers all the text it did. A repaired load shows every character a plain load shows, only characters a plain load or the repair without its rules shows, each with the formatting one of them gives it, and each node attribute or NodeState value as one of them has it: when nothing is held back and no entry the document shows is overwritten, that holds as the repair applies, at its old cost; otherwise the load is checked on a copy of the document first, and the repair without its rules, or the plain load itself, is applied when the held plan does not pass. A run that carries text integrates even if a format of its own stays unpaired, so formatting can briefly differ from both a plain load and the healed document until the gap heals.

Verify: on a document where an update lost before the next one blocks a format's closer (one update inserts text after the lost text, then formats a range ending at it), load `encodeStateAsUpdate` of a peer that holds that update pending through `createYDoc` or `readYState`: no bold appears where the peer showed none, the text is the peer's, and once the lost update arrives the document is byte-identical to a plain load.
