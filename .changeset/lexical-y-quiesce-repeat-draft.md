[fix] `quiesce()` called again returns the first call's draft, so a retried handoff keeps unwritten text

`YBinding.quiesce()` called again (before or after `dispose()`) returns a copy of the first call's result: the same state and the same draft, `differs` included. When the first call refused the editor's batched update (the binding was already read only, or the record stopped admitting writes during the call), that update was its draft with `differs: true`, but the refusal read the document back into the editor and a second call rebuilt the draft from it, without the unwritten text and with `differs: false`: a retried handoff lost what the user typed. Later calls now recompute nothing; what was written to the document after the first call is not in their state. The draft is the editor state's JSON (what a quarantine record stores), kept as text: every result, the first included, is its own copy, parsed again, so it holds only plain JSON values: a `Date` NodeState value is its ISO string, `NaN` or `Infinity` is `null`, a `Map` or `Set` is `{}`, and an `undefined` array entry is `null`. Before draining, `quiesce()` checks that the state that will become the draft serializes as JSON (the pending update's, or with none pending, the shown one): a failure at that preflight (a `BigInt` NodeState value, a cycle, a node's `exportJSON` that throws) throws a `TypeError` naming the cause, without draining or quiescing. If app code produces a non-serializable state during the drain, the final serialization may throw a `TypeError` after local work has been written and the composition has ended, with nothing cached: fix the state and retry `quiesce()`, and don't assume earlier edit callbacks didn't run. A warning handler that calls `quiesce()` while the first call's warnings are delivered gets the first call's result.

Verify: with a batched edit pending on a read-only binding (or one whose layout record turns newer during the call), call `quiesce()`, then call it again, including from an `onWarn` handler for the refusal's `UNSUPPORTED_EDIT_WARNING`: every result's draft holds the unwritten text with `differs: true`. Mutate one result's state bytes and draft: a later call is unchanged. Call `binding.dispose()` and `quiesce()` again: the same result. Apply a later update to the document: a later call's state still equals the first call's. With a Date NodeState value, the first and a repeated draft hold the same ISO string; with a BigInt one, `quiesce()` throws a `TypeError` and the binding stays as it was. Have an update listener set a BigInt NodeState value during the drain: `quiesce()` throws the drained-state `TypeError`, the pending text is stored and nothing is cached; with serializable state, a retry hands off. Apply another replica's update between two calls: their state bytes are equal. Make a node's `exportJSON` throw: `quiesce()` throws a `TypeError` naming that error and changes nothing. With a BigInt NodeState value shown and a pending update that replaces it with `1`, `quiesce()` hands off.
