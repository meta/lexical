[feature] Layout migrations for stored documents (experimental): `MIN_LAYOUT`, the oldest layout the binding reads (1, so nothing changes for existing documents), with a read-only gate below it (an `onOlderLayout(found, min)` option; `UNSUPPORTED_LAYOUT_WARNING` `{reason: 'older', found, min, supported}` to `onWarn` only for an app with neither `onOlderLayout` nor `migrateLocally`, since its development default throws); `@lexical/y/migrate`, a runner that migrates a stored state or a live document with frozen steps, one per layout (`@lexical/y/migrate/1to2`), checking the result on a copy before anything is written and recording the layout and an epoch (`lexical-y-epoch`; a malformed epoch opens the document read only, like a malformed layout record); `migrateLocally` for documents only one client writes; `binding.quiesce()` and `onLayoutEpoch` for handing a replica off and clearing undo; `SEED_LAYOUT`; and `@lexical/y/server`, the pieces a server uses to migrate a room on load and keep stale sessions apart (`prepareYRoom`, `generationOf`, `checkYSession` with seed contracts, `captureYSession` and legacy signals, quarantine records, and a Yjs-only `createYDoc` for a relay's documents)
